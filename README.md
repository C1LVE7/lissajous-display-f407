# 李萨如图形显示控制装置

STM32F407 + AD9834 的相位闭环装置，2026 年电子设计竞赛 F 题实现。

信号源接输入端，本板合成一路正弦接示波器 Y 通道，X 通道接信号源本身。两路频率成整数比、相位固定时，屏幕上出现静止的李萨如图形。装置要保证这个图形**不转**，并按题目要求切换同频/二倍频、0°/90° 相位与四档幅度。

裸机前后台架构，无 RTOS。

---

## 1. 问题与思路

难点不在产生正弦，而在让图形不转。

信号源和本板是**两颗独立晶振**，频率不可能完全一致。哪怕只差 0.1 Hz，相位差也会持续累积，屏幕上的图形就缓慢旋转。开环写一个固定频率字永远解决不了这个问题。

所以这里做的是**闭环控相**：每 5 ms 同时采一次参考信号与自身输出，测出两路各自的频率与相位，用比例积分算出该往哪个方向调多少频率，写回 DDS。频差被持续抵消，相位差被摁在目标值上。

整条闭环**不在代码里闭合**：程序改的是 DDS 频率，相位差在模拟电路中改变，下一帧再从 PA2 采回来成为新的输入。代码里没有一行在"等"信号——是定时器在推、中断在搬、主循环在算。

```text
信号源 ──► 调理 ──► PA1 / ADC1 ┐
                                ├─ TIM3 同一触发沿 ─► DMA 乒乓 ─► 1024 点 FFT
DDS 输出 ─► 调理 ──► PA2 / ADC2 ┘                                    │
     ▲                                                              ▼
     │                                                    测频 / 测幅 / 投影测相
     │                                                              │
     └──────── 写 AD9834 频率字 ◄──── PI 锁相环（5 ms 一拍） ◄────────┘
```

## 4. 使用

### 4.1 接线

1. **断电接线**，确认 STM32、AD9834、信号源、示波器、USB-TTL 全部共地。
2. 信号源经调理电路接 **PA1**。
3. AD9834 输出接示波器 **Y 通道**，同时经限幅、衰减、1.65 V 偏置后接 **PA2**。
4. 示波器 **X 通道**接信号源本身（不是接本板）。
5. 四个按键一端接对应引脚、另一端接 3.3 V；显示屏插核心板 TFT 排母，断电插拔。

**安全边界**：PA1、PA2 任何时刻都必须满足 `0 V ≤ V ≤ 3.3 V`。不得直接输入负压或 RS-232 电平；AD9834 输出不能未经调理直接进 ADC。

### 4.2 上电

初始化顺序固定：`HAL_Init → 时钟树 → GPIO → DMA → TIM3 → ADC1 → ADC2 → USART1 → TFT → SignalApp`。

**DMA 必须先于 ADC 初始化**，因为 ADC 初始化时要挂 DMA 句柄，顺序反了就挂空。

初始化只配置外设，不启动采集；真正的第一个采样点发生在 `SignalApp_Resume` 里的 `HAL_TIM_Base_Start`，此时采样率直接设为 1 MHz（最高档、已知安全态）。

上电后屏幕显示题号「一」，串口开始每 200 ms 输出状态。在 PA1 检测到有效输入之前，DDS 保持软件复位、无波形输出。

### 4.3 四个按键

四个键共用一套消抖：读电平 → 连续 20 ms 稳定 → **稳定为高时上报一次**。

- 引脚配置为**下拉**，所以未按为低、按下为高；触发点是「按下并稳定 20 ms」，不是松手。
- 按住不放不会连发：稳定之后采样值不再变化，不会重复进入判定。

| 按键 | 引脚 | 动作 | 清掉什么 |
|---|---|---|---|
| 同频/二倍频 | PE3 | 基波 ↔ 二倍频往复 | 锁相环 9 个字段 + 丢帧计数 + 名义频率，从零重新捕获 |
| 0°/90° | PE2 | 目标相位翻转 | 只作废 3 个结论字段，不动硬件与积分器，几帧即可重锁 |
| 输出档位 | PE4 | 示波器 8 / 6 / 4 / 2 格循环 | 无。切到视觉模式后仍然有效，因为它控的是示波器那一路的衰减 |
| 进入视觉 | PA0 | 切第五题模式 | 只在正常模式可读，进入后不再响应 |

### 4.4 输出档位

PB4 ~ PB7 控制后级衰减/放大网络，对应示波器 8、6、4、2 格。

切换用**一次 BSRR 写**完成：选中位写进高 16 位（拉低），其余三位写进低 16 位（拉高）。一个写操作同时生效，避免中间态在示波器上产生毛刺。

### 4.5 串口输出

USART1，115200-8-N-1，每 200 ms 两行：

```text
PA1 F=10000.000Hz Vpp=1980mV | DDS_FB F=10000.000Hz Vpp=1000mV
PLL E=-0.120deg TARGET=0.000deg CMD=9999.880Hz NOM=10000.000Hz DF=0.000Hz TRIM=-0.120Hz PCORR=0.000Hz VALID=1 LOCK=1
```

| 字段 | 含义 |
|---|---|
| `PA1` | 参考路实测频率与峰峰值（毫伏） |
| `DDS_FB` | 反馈路实测频率与峰峰值 |
| `E` | 当前相位误差，单位度（内部用毫度整数保存） |
| `TARGET` | 目标相位，0° 或 90° |
| `CMD` | 实际写给 DDS 的命令频率 |
| `NOM` | 名义频率（参考路测频结果 × 倍频数） |
| `DF` | 频率误差 |
| `TRIM` | 积分腿输出的频率微调量 |
| `PCORR` | 相位环贡献的频率修正量 |
| `VALID` | 本帧测量是否有效 |
| `LOCK` | 是否已锁定 |

格式化全部手写数字转字符，没有调用 `printf` 的浮点格式化——那会把 Flash 撑大一大截，这里只支持定点三位小数。

三个节拍计时器（5 ms 分析、200 ms 打印、5 s 重探）各自独立。合并成一个变量的后果是：5 ms 那一轮每次都刷新计时，200 ms 判据永远差 5 不够 200，串口一行都打不出来。

### 4.6 屏幕

| 场景 | 显示 |
|---|---|
| 上电 / 切题 | 题号大字（一、二、三、五） |
| 第四题 | 当前档位格数 |
| 视觉模式 | K230 上报的频率，数值变化时刷新 |

事件驱动刷新，不做周期重绘。

### 4.7 典型操作

1. 断电接线，确认共地；示波器 X 接信号源、Y 接 DDS 输出。
2. 上电，屏幕显示「一」，串口应稳定输出 `PA1 F=…` 且 `VALID=1`。
3. 信号源输出 1 kHz 正弦，幅度调到示波器上便于观察。
4. 观察串口 `LOCK` 由 0 变 1、`E` 收敛进死区，屏幕图形停止旋转。
5. 按 PE3 切二倍频；按 PE2 切 90°（图形在直线与椭圆之间变化）。
6. 按 PE4 逐档切幅度，示波器上图形尺寸随之变化。
7. 需要第五题时按 PA0，USART3 初始化，主控等待 K230 上报。

## 5. 工作原理

### 5.1 采样：为什么缓冲是 2048 点

TIM3 每触发一次，两路 ADC 同时转换，各自 DMA 循环写入 **2048 点**缓冲，半满和全满各中断一次；中断把对应的 1024 点拷进 `adc_stable_frame`，两路都到齐后置 `frame_ready`。

缓冲取 2048 而不是 1024，是为了做**乒乓**：CPU 拷前半时 DMA 正在写后半。改成 1024 就只剩全满回调一条路，而全满触发的瞬间 DMA 已经绕回开头覆盖，帧头会混进新样本——在 100 kHz 信号上相当于相位错几百度的量级。

`frame_ready` 本质是容量 1 的队列：

| 动作 | 效果 |
|---|---|
| 上锁 | 两路齐了置 1 |
| 挡写 | 已为 1 时中断直接 `return`，连 memcpy 都不做——新帧是**主动丢弃**，不是溢出 |
| 借出 | 为 0 时返回 `NULL` |
| 归还 | 清 0 |

**借了必须还**。主处理有四个出口都要归还（反馈帧空、要换档、写 DDS 失败、正常结束）。漏一个的后果是数据永久冻结、但函数照样每帧返回成功——屏幕数字停住不动，不报警，这是最隐蔽的故障。

### 5.2 采样率如何算出来

`total = 84 MHz / fs` 四舍五入 → `PSC = ceil(total / 65536)` → `ARR = 84 MHz / (fs × PSC)`，写入寄存器时各减一。

TIM3 是 16 位，装不下 84000 这么大的比值（1 kHz 档），所以必须拆成预分频与周期两段。100 kHz 档总数只有 840，不用拆。

四档都是 84 MHz 的整除因子，请求值等于实际值，没有分频误差。

换挡顺序固定：**停表 → 停采集 → 改时基 → 启采集 → 开表**。`SignalAcquisition_Stop` 必须在 `SetSampleRate` 之前，因为后者开头判「ADC 句柄非空就返回 0」，不先清空必然失败。

### 5.3 测频：三谱线插值

去直流 → 乘汉宁窗 → 1024 点复数 FFT → 取模 → 在 1 ~ 511 格找最大 → 三谱线插值 → 换算频率。

- 汉宁窗用**对称型**，分母 1023 不是 1024，让首尾两点重合、窗连续。
- 插值式 `δ = 2(R−L)/(L+2C+R)` 是汉宁窗主瓣形状的专用式，比通用抛物线拟合偏差小；限幅 ±0.5 格，因为它只在峰位于中央格时才成立。
- `f = (index + δ) × fs / 1024`。

1 MHz 采样下格宽 976.56 Hz，插值后误差约 ±0.05 格 ≈ ±48 Hz，题目要求 100 Hz 步进，余量约两倍。

### 5.4 测幅：为什么不用时域峰峰值

采样点不一定落在峰顶，落偏一点读数就差一截，而且每帧落点不同，读数会跳。

所以幅度用**整帧正交投影拟合**：已知准确频率，就把 1024 点按正弦形状投影，反推幅度。

```text
Vpp_mV = 4 × |V| × 3300 / (窗和 × 4095)
```

那个 4 来自两处：投影本身带 1/2（正弦乘正弦只有直流项存活），峰值换峰峰再乘 2。读数超过 3300 mV 时钳位。

时域峰峰值仍然在用，但只作为有效性门限（124 码），不参与测量值。

### 5.5 测相：两个负号与一次倍频

设信号 `y = A·sin(ωn + φ)`，与余弦相乘累加得到正比于 `sin φ` 的量，与正弦相乘累加得到正比于 `cos φ` 的量，`atan2` 出 φ。

代码里累加用 `quadrature -=`，`atan2` 里又写 `-quadrature`，**两个负号必须配对**。只删一处会得到 `180° − φ`，整个相位镜像；而锁定判据会把这个固定偏差当成待追的目标，永远锁在错的位置。

两路投影频率不同：参考路用自己的频率，反馈路用「参考频率 × 倍频数」。这是**角速度对齐**——二倍频时反馈路的角速度是两倍，不乘就没法在同一尺度上比较。

相位窗随频率变化，按格号选 256 / 512 / 1024 点，取帧尾最新的一段。高频一帧有几十个周期，用满窗最稳；低频一帧只有几个周期，硬用 1024 点等于把大部分权重浪费在窗两端（汉宁窗端点权重接近零），所以缩到 256 点。

### 5.6 自动量程

格号（等于一帧内的周期数）低于 8 降一档、高于 400 升一档、8 ~ 400 之间不动，每次差十倍。

三道保护：

1. 到底不再降、到顶不再升，返回自身让上层判等后跳过，省掉一次硬件重启。
2. 升档前有夹子：请求超过 100 kHz 直接给 1 MHz。否则 200 kHz 乘 10 得 2 MHz 会被上下限检查拒绝、返回 0，一路传到停机。
3. 每 5 秒无条件回最高档重探。混叠时假峰可能正好落在 8 ~ 400 窗口内，判据自己发现不了错误，只能定期回到已知安全态重来。

### 5.7 锁相环

被控量是相位、控制量是频率，而相位是频率的时间积分——中间天然有一个积分环节。**纯比例必然有稳态误差，所以必须 PI。**

七步：入口检查 → 跟踪频率 → 捕获门 → 算相位误差 → 积分 → 比例 → 合算写频、判锁定。

| 环节 | 做法 |
|---|---|
| 跟踪 | 捕获时直接赋值；跟踪时一阶低通，α = 0.25 |
| 捕获门 | 已下发与实测频率差超过 `max(0.5%, 50 Hz)` 就重新捕获 |
| 相位误差 | `参考相位 × 倍频数 + 目标 − 反馈相位`，折到 ±180° |
| 积分 | 误差在 0.1° ~ 20° 之间才积；限幅 ±2% 标称频率 |
| 比例 | 误差 > 10° 用 0.30（快档），否则 0.20；死区 0.1° 内归零 |
| 写频 | `标称 + 积分 + 比例`，与上次相差 ≥ 0.5 Hz 才写 |
| 锁定 | 相位 ≤ 5°、频率误差 ≤ max(500 ppm, 5 Hz)、**连续 5 帧**，任一帧不合格就清零重来 |

三个保护分别防三类问题：

- **积分门 20°**：误差大时禁止积分。否则积分量被推远，等误差回来时还在同方向推，造成长时间过冲——积分饱和。
- **积分限幅 2%**：不管怎么累积，最多只推标称频率的 2%。
- **比例限幅 75 Hz**：按参数算要误差到 250° 才撞得上，而误差已折到 ±180° 内，实际永不触发。它的作用是参数被改坏时兜底。

所有门限用「相对量 ppm」与「绝对下限」取大，交叉点在 10 kHz。原因是低频时 ppm 折算出来比芯片分辨率还小，只配相对量会永远判不合格。

**两个清除函数分工不同**：`DdsPll_Reset` 清 9 个字段（含 6 个调频历史），用于换频点、上电、静音；`DdsPll_Invalidate` 只清 3 个结论字段，用于相位键和采样率变化——频率没变，历史还能用，几帧就能重锁。

**静音与恢复**：峰连续无效 20 帧（100 ms）就软件复位 DDS 静音、清名义频率、重置锁相环。信号回来后因为名义频率是 0，任何有效频点都不等于 0，必然触发重写——一帧内自动恢复。

### 5.8 写 DDS：两条路径不能混

同一个芯片两个入口，混淆就是那个"串口数字全对、频率读数很准、唯独图形一直在转"的经典故障。

| 场景 | 顺序 |
|---|---|
| 换频点 | 软件复位 → 相位字写 0 → 写频率字。顺序不能变，复位会冲掉刚写的 |
| 闭环微调 | **只用不复位的接口**，只改频率 |

闭环若误用带复位的接口，每 5 ms 把 28 位相位累加器清零一次，波形一直被拉回原点，相位永远追不上。

相位字在本工程里**永远写 0**：写相位字会让波形跳变、示波器上可见毛刺，所以相位一律靠调频连续追。

写频死区取 0.5 Hz，是因为 DDS 一步 0.279 Hz，死区必须大于一步。

## 7. 编译与烧录

├── Middlewares/ST/ARM/DSP/       CMSIS-DSP 静态库

├── MDK-ARM/                      Keil 工程

模块规模：`main.c` 379 行、`signal_app.c` 441 行、`signal_acquisition.c` 227 行、`FFT.c` 330 行、`dds_pll.c` 251 行、`serial_log.c` 209 行、`tft_display.c` 693 行、`vision_slave.c` 667 行、`ad9834_gpio_f407.c` 700 行。

主循环只有四条互斥路径：进视觉键（带 `continue`）→ 档位键（无条件）→ 正常模式三连 → 视觉模式单函数。

进视觉键的 `continue` 不能省：它执行后 `app_running` 已被清 0，不跳过就会在下一句判失败、立刻停机。

## 9. 已知限制与取舍

1. **换挡有盲区**：停表到开表至少丢一帧，换挡成功还作废锁相环结论、要重新捕获 5 帧。每换一次档约 25 ms 未锁定。
2. **混叠可能卡错档**：判据只看峰在不在窗口，不看峰是否真实。假峰落在窗口内就永远不动，只能靠 5 秒重探兜底，不能根除。
3. **低频相位精度不如高频**：一帧只有几个周期，窗还要压掉两端，等效积分长度短。这是"响应换精度"的有意取舍。
4. **频率分辨率被 1024 点锁死**：想更准只能加点数，代价是帧时间与运算量翻倍。
5. **失败即停机**：任何 HAL 初始化失败都进 `Error_Handler`（关中断 + 死循环），没有重试与恢复路径。这是为了现场快速暴露接线问题，不是疏忽。
6. **幅度不在软件闭环内**：AD9834 只受频率与相位寄存器控制，幅度由 PB4 ~ PB7 选外部增益档位。
7. **第五题的视觉算法在 K230 侧**：本仓库只含主控侧的从机协议。

真正吃 CPU 的只有两件事：把分析节拍从 5 ms 压到 2.5 ms，或把 FFT 从 1024 点加到 2048 点。其余功能都没有被 CPU 卡住，当前配置是刻意留了余量的保守选择。
